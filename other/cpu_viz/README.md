# RISC-V RV32I 单周期 CPU 数据通路可视化工具

## 这是什么？

一个**纯前端网页**，用动画直观展示 RISC-V RV32I 单周期 CPU 中，不同指令在数据通路（Datapath）上是如何流动的。

打开 `visualizer.html` 就能用，无需安装任何东西。

## 能干什么？

- 在左侧下拉菜单选择指令（ADD、LW、SW、BEQ、JAL 等 12 条指令）
- 右侧 SVG 图会**高亮**该指令经过的组件、数据路径和控制信号
- 活跃路径有**流动的虚线动画**，清楚展示数据方向
- 侧边栏实时显示控制信号的值和指令编码格式
- 用**键盘上下左右键**也能切换指令

## 适合谁用？

- 正在学计算机组成原理/体系结构的学生
- 需要备课讲 RISC-V 数据通路的老师
- 想快速理解某条指令在硬件层面如何工作的工程师

## 创新点

### 1. 声明式配置，零命令式逻辑

每条指令的数据通路配置就是一个 JS 对象，只声明"哪些组件亮、哪些路径走、哪些控制信号活跃"。切换指令时没有一长串 if/else，新增指令成本极低。

```js
"ADD": {
    comps: R_COMPS,     // 复用 R 类型通用组件列表
    paths: R_PATHS,      // 复用 R 类型通用路径配置
    ctrl: { vals: { ALUOp: 'ADD' } }  // 只覆写不同的字段
}
```

### 2. CSS 类驱动激活

所有视觉变化（发光、描边颜色、透明度、动画）全部通过切换 CSS 类实现，不写一行内联样式。样式和行为完全分离，改配色只需改 CSS 变量。

### 3. 三层颜色架构

- **流水线阶段颜色**（5 种）：蓝紫橙黄绿 → 取指/译码/执行/访存/写回
- **控制信号颜色**（7 种）：品红/青/紫/红/绿/蓝/橙 → 8 条控制线各有一种颜色
- **非活跃默认色**：深灰蓝 → 当前指令未使用的组件和路径

### 4. 主干路径（Trunk Path）模式

组件输出到多路径汇合点之间画一条"主干"，再从汇合点分支出去。这解决了传统画法中组件输出端多条路径叠在一起导致的**视觉缺口**问题——这是对渲染正确性的关键修复。

### 5. 透明度策略解决 SVG 绘制顺序

非活跃路径用 `opacity: 0.18`，即使按 SVG 源码顺序后绘制，也不会在视觉上遮盖活跃路径。避免了动态 DOM 重排序的复杂性和性能开销。

### 6. 基于 x 坐标的组件-阶段自动映射

初始化时通过 `getBBox()` 获取每个组件在 SVG 中的 x 坐标，与阶段列边界比对，自动判断每个组件属于哪个流水线阶段。之后每次切换指令直接查表，无需重复计算。

### 7. 严格的 6 步渲染流水线

`updateDatapath()` 按固定顺序执行：清除 → 文本 → 信号 → 阶段 → 组件 → 数据路径 → 控制路径。每一步职责清晰，最小化视觉闪烁。

### 8. 单文件零依赖

一个 HTML 文件包含所有 CSS 和 JS，没有框架、没有构建工具、没有后端。双击即用，方便分享和部署。

## 已支持的指令（12 条）

| 类型 | 指令 | 说明 |
|------|------|------|
| R 类型 | ADD, SUB, AND | 寄存器间算术/逻辑运算 |
| I 类型 | ADDI, ORI | 立即数算术/逻辑运算 |
| 加载/存储 | LW, SW | 内存读写 |
| 分支 | BEQ | 相等则跳转 |
| U 类型 | LUI, AUIPC | 高位立即数加载 |
| 跳转 | JAL, JALR | 无条件跳转并保存返回地址 |

## 技术栈

纯 HTML + CSS + SVG + 原生 JavaScript，零依赖。
